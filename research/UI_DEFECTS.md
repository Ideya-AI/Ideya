# Standing UI-defect register

The single source of truth for **site-wide** code/CSS defects found by stage-4 view
critics. Per-topic content findings never go here — they go through the `fix_only`
loop. The pipeline never fixes these (it may not touch templates/CSS); the human
burns this list down.

How it's used (ENGINE.md §5 stage 4): the view critics receive this file with the
renders. A finding that matches an OPEN entry is **not** re-reported in the packet
(cite the entry instead); a finding that matches a FIXED entry means a regression —
report it loudly. A genuinely new site-wide defect goes in the packet AND is
appended here by the orchestrator.
