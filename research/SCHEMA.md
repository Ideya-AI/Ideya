# `topic.json` — the schema

One file per topic at `research/topics/<slug>/topic.json`. The directory name is
the slug. Index fields at the top, `content` under them once there is content.

**Array order is display order.** No order field anywhere. Moving an item across
the fold means moving it in the array.

**Plain text everywhere**: `&` not `&amp;`, typographic quotes, no markdown, no
HTML, US spelling except inside a proper noun.

**The database is fully derived.** `load_universe` rebuilds every topic from
this directory, so the file wins over the database in every disagreement.

**Participation is not here.** Votes, leans, prompt responses and events live in
the database, keyed by item `id`. Ids are assigned once from the item's text and then
frozen, so rewording an item keeps its reader data; re-authoring a topic must
preserve them or the participation detaches. Prompts are generated by the loader.

**Images** are found by slug: `static/img/topics/<slug>.png` and
`static/img/social/<slug>.png`. `primary_image_prompt` keeps the provenance of
that art in the file; the fuller brief stays in `icon.md`.

```jsonc
{
  "slug": "nuclear-energy",            // equals the directory name
  "title": "Nuclear Energy",           // <=200
  "status": "not_started",             // not_started | in_progress | ready | published
  "authored_at": null,                 // ISO 8601, set when the authoring skill finishes
  "published_at": null,                // ISO 8601, set when the human publishes
  "reviewed_at": [],                   // one ISO 8601 per review-skill run, oldest first
  "scope": "...",                      // one sentence, <=400
  "icon": "atom",                      // Phosphor glyph name, <=80; written by stage 3
  "primary_image_prompt": "...",       // the prompt the topic's art was generated from
  "primary_category": "climate-energy",// slug; also the color key (--cat-<slug>)
  "categories": ["economy"],           // secondary categories, may be empty
  "related": ["firm-power-vs-renewables", "net-zero-pace"],

  "content": {
    "overview": {
      "summary": "...",                // <=400
      "scope_covered": "...",          // <=400
      "scope_excluded": "...",         // <=400
      "why_now": "...",                // short paragraph, a dated recent event
      "why_now_source_label": "...",   // <=120, the outlet or body that reports it
      "why_now_source_url": "https://..."
    },

    "basics": {
      "stats": [                       // 10-20 tiles, first 3 packed rows shown
        {
          "id": "st_...",
          "label": "...",              // <=120, the metric, not a sentence
          "viz": "bar",                // bar | radial | ranked | range
          "wide": false,               // spans 2 of 3 columns; ranked tiles are wide
          "value": "0.03",             // <=24, empty for ranked
          "unit": "deaths/TWh",        // <=24
          "series": [                  // ranked only; one shared unit
            { "label": "Coal", "value": "24.6", "highlight": false }
          ],
          "range_min": "",             // range only
          "range_max": "",             // range only
          "note": "...",               // <=400, states the value
          "detail": "...",             // paragraph, shown when the tile expands
          "source_label": "...",       // <=120
          "source_url": "https://...",
          "source_published": "2024",  // <=40, when the data is from
          "source_accessed": "2026-09-16"
        }
      ]
    },

    "questions": [                     // 5-8, first 4 shown
      {
        "id": "q_...",
        "text": "...",                 // <=400, open question
        "kind": "empirical",           // empirical | value
        "why": "...",                  // why it is contested
        "detail": "...",
        "lean_label_a": "...",         // <=40, the two poles readers pick between
        "lean_label_b": "..."          // <=40
      }
    ],

    "positions": [                     // 3-6, first 4 shown
      {
        "id": "p_...",
        "name": "...",                 // <=120, what the camp wants
        "color_key": "green",          // --pos-* token, unique within the topic
        "steelman": "...",             // <=400, the glance layer: the case in one
                                       // breath, rendered as the camp's own quote
        "detail": "...",               // the expanded layer: the camp's case in its
                                       // own voice. A named adherent belongs here,
                                       // in prose, only when they make the camp legible
        "proponents": "..."            // semicolon-separated names
      }
    ],

    "crux": {
      "lead": "...",                   // <=240
      "lead_highlight": "...",         // a phrase copied verbatim from lead
      "subtitle": "...",
      "empirical": "...",
      "values": "..."
    },

    "actions": [                       // 6-10, first 6 shown
      {
        "id": "a_...",
        "kind": "learn_more",          // learn_more | donate | volunteer | policy | local
        "title": "...",                // <=200
        "description": "...",          // <=400
        "url": "https://...",
        "for_position": null           // a position's name, or null when neutral
      }
    ]
  }
}
```

## Derived by code, never authored

`fill_pct` and `range_at` on a stat, and `pct` on a series row. Computed from
the values. They appear in exported files because the exporter round-trips them.

## Open

- `proponents` is one string; an array would be cleaner.
- `for_position` matches a position by name, so renaming a position breaks it.
  Matching on the position's `id` would be sturdier.
